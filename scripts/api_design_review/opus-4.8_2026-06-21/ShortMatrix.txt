API Design Review — ShortMatrix
MODEL opus-4.8 | DATE 2026-06-21 | file: src/main/java/com/landawn/abacus/matrix/ShortMatrix.java (3836 lines)
All findings verified against source.

1. OVERALL ASSESSMENT
A well-built, highly consistent member of the narrow-integer tier. Implementations were read across factories,
accessors, diagonal ops, update/replace/map, fill/copy/resize/extend, flips/rotations/transpose/reshape,
repeat ops, flatten/mutateViaFlatArray, stacking, arithmetic, zipWith, all stream families, forEach, and
equals/hashCode/toString/println. Element-wise arithmetic correctly documents and implements short->int
promotion with narrowing back to short, with accurate overflow guidance (widen via toIntMatrix/toLongMatrix).
Conversions are complete and correct (toInt 2699, toLong 2721, toFloat 2762, toDouble 2803). Validation
conventions match the family (get/set->AIOOBE; value*->OptionalShort + IOOBE; null->IAE; non-square->ISE). The
substantive class-specific gap is a missing from(byte[]) widening factory; the missing static Matrices.zip is
a hub-level gap shared with Char/Float. No correctness bugs; no @Deprecated members.

5. MISSING METHODS

from(byte[]...) | ShortMatrix.java:140 (ShortMatrix has NO from(...) at all — only of(...)) | Confidence High |
recommend: add public static ShortMatrix from(final byte[]... a) (sign-extending widening, rectangular
validation, empty short-circuit), mirroring IntMatrix.from(byte[]...) (IntMatrix.java:210).
  > public static ShortMatrix of(final short[]... a) {     // no from overload exists
  byte->short is a valid widening; IntMatrix establishes the from pattern for narrower integral sources.
  (ByteMatrix correctly has no from — byte is narrowest — so its absence is not a precedent against this.)

Static Matrices.zip / zipToInt for ShortMatrix | absent at the hub | Confidence Medium | recommend: add
Matrices.zip(ShortMatrix,...) family + zipToInt(ShortMatrix,ShortMatrix,ShortBiFunction<Integer,E>), mirroring
the Byte family.
  > Matrices has zip for Byte/Int/Long/Double only; ShortMatrix.zipWith exists (2865/2923) so the static
    mirrors are trivial. Hub-level consistency gap, not a hard functional hole. (Family item — see SUMMARY.)

mapToInt/mapToLong/mapToDouble | absent (only mapToObj) | Confidence Low | recommend: optional, decide at
family level (pairs with existing toInt/toLong/toDouble converters; uniform absence across the narrow tier).

CROSS-CLASS NOTES
- from absent in ShortMatrix but present in IntMatrix; the applicable widening is byte->short — the single most
  actionable Short-specific gap.
- Matrices.zip/zipToInt absent for Short; present for Byte/Int/Long/Double.
- mapToLong/mapToDouble absent — NOT a divergence to fix in isolation; it is the verified narrow-tier
  convention (Byte/Char likewise have only map + mapToObj).
- Everything else tracks the IntMatrix baseline faithfully (incl. @Beta markers on the verticalStream/
